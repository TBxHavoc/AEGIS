# Architecture

`main.py` loads validated settings, configures logging, installs signal handlers, and owns graceful shutdown. `backend/api/server.py` provides a threaded HTTP server, REST health/status endpoints, static frontend delivery, and WebSocket upgrade handling. `backend/api/websocket.py` contains the small RFC 6455 framing layer needed for the restored interface without installing a dependency.

Sessions are bounded and in-memory in `backend/conversation/session.py`, with opt-in SQLite message persistence in `backend/conversation/persistence.py`. Conversation context and streaming are coordinated by `backend/conversation/engine.py`. The provider-independent `backend/inference/engine.py` wraps a one-model-at-a-time `ModelManager`; `ModelRegistry` discovers local GGUF files and `LlamaCppProvider` loads them lazily. The optional `llama-cpp-python` runtime is not part of base requirements. With no configured model/runtime, inference reports unavailable. `backend/memory/store.py` provides category-separated, privacy-filtered local memory, with a bounded relevant subset passed into context. Intelligence contracts remain separate from deterministic helpers so heuristics are not misrepresented as model reasoning.

Voice is isolated under `backend/voice/`: `VoiceService` owns TTS request de-duplication and lifecycle, `PiperProvider` is an optional local TTS adapter, and `AudioPlayback` owns the single playback process. Phase 5 adds `backend/voice/stt/` with bounded PCM validation, replaceable whisper.cpp and Vosk adapters, local VAD, and normalization. Browser microphone input streams through the existing WebSocket and reaches the same `CentralBrain` path as typed input. Providers remain unavailable until configured with local runtimes/models; see [VOICE_RECOGNITION.md](VOICE_RECOGNITION.md) for setup and limits.

`backend/intelligence/reasoning.py` adds Phase 3 structured understanding and task planning. It uses the existing `InferenceEngine` contract for optional model-backed JSON extraction and a deterministic, low-confidence classifier when no model is available. Plans pass structural validation before the orchestrator invokes registered tools through `ToolRegistry` and `PermissionPolicy`; generated commands are never executed. SQLite task history is stored separately in `data/reasoning_tasks.db`. See [REASONING.md](REASONING.md) for status and limitations.

Phase 4 adds a persistent protocol subsystem in `backend/protocols/`: deterministic draft parsing, schema and permission validation, SQLite lifecycle/version snapshots, scope-aware resolution, conflict and priority handling, and compliance reports. Only active protocols enter bounded reasoning context and task plans. Drafts cannot activate themselves; local mutation APIs require explicit confirmation for lifecycle changes. Protocol text cannot override the system policy or registered tool permissions. See [PROTOCOLS.md](PROTOCOLS.md).

Phase 6 adds `backend/agents/` as a specialist workflow layer owned by `CentralBrain`. The registry exposes nine specialist definitions, while one bounded orchestrator classifies and plans relevant work, resolves active protocols, checks policy, runs bounded workflows, verifies structured results, and supplies them as untrusted reference data to the existing shared inference engine for one final response. Voice transcripts and typed messages use the same brain path. The agents do not load separate models. See [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md), [SPECIALIST_AGENTS.md](SPECIALIST_AGENTS.md), and [MULTI_AGENT_ORCHESTRATION.md](MULTI_AGENT_ORCHESTRATION.md).

Phase 7 extends the existing `ToolRegistry` with bounded schemas, filesystem operations under configured roots, read-only host diagnostics, in-memory CSV/JSON analysis, sandboxed test discovery when bubblewrap is available, optional HTTPS web research, and an explicitly connected MCP HTTP client. The scheduler now persists approved named workflows and restores them paused. All external and file actions remain allowlisted and policy-gated; details and unsupported capabilities are listed in [TOOL_ARCHITECTURE.md](TOOL_ARCHITECTURE.md).
