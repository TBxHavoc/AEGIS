# AEGIS Brain and inference boundary

The current central brain (`backend/intelligence/brain.py`) prepares a request using deterministic intent metadata and a small, relevant set of approved memory categories. It passes those memory excerpts and the configured system instruction into the bounded conversation context. The model remains the source of generated response text; without an available model, AEGIS emits an explicit inference-unavailable failure.

`ConversationEngine` owns per-session history, cancellation, and the existing WebSocket stream events. It delegates requests to the provider-independent `InferenceEngine`, which owns timeouts, generation defaults, and usage/latency observations. `ModelManager` loads one local model on demand, checks a conservative memory budget, unloads it before a model switch, and reports load errors. `ModelRegistry` discovers only local `.gguf` files; it never downloads a model.

Retrieved memory is bounded to five relevant excerpts from explicit, long-term personal, short-term, or retrieved-knowledge categories. Conversation history is bounded separately. Saved memories are framed as reference data that cannot override system instructions. Conversation history persistence remains opt-in.

The Phase 3 reasoning layer is in `backend/intelligence/reasoning.py`. It adds structured intent fields, dependency-aware plan validation, optional provider-backed classification, bounded context construction, registered-tool execution, SQLite task history, and result checks. Without an available real model, intent classification remains deterministic and limited. Phase 6 adds deterministic specialist workflows through `MultiAgentOrchestrator`; these do bounded retrieval and analysis and do not act as separate conversational models. Their structured results are independently checked for identity, shape, evidence gaps, and conflicts, then passed to the central model as reference data for final synthesis. See [REASONING.md](REASONING.md) and [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md).

Phase 4 connects active user protocols to task reasoning. The resolver chooses relevant active versions by category, scope, triggers, and priority; unresolved conflicts, unverifiable preconditions, and permission requirements above policy block execution. Plans retain protocol IDs and versions and track each protocol procedure in a compliance report. Drafts and revisions require approval before activation; the local API confirmation gate does not create remote user authentication. See [PROTOCOLS.md](PROTOCOLS.md).

Phase 7 connects CentralBrain and specialists to real local tools through `ToolRegistry`. Direct tool API calls and scheduler workflows resolve relevant active protocols; agent tasks resolve protocols before their scoped tool callbacks. Permissions are rechecked on every invocation. File access is root-bounded; test runs require a confirmed local request and a bubblewrap snapshot; web/MCP access is opt-in; there is no unrestricted shell. A model can propose tool inputs but cannot execute them outside this boundary. See [TOOL_ARCHITECTURE.md](TOOL_ARCHITECTURE.md).
